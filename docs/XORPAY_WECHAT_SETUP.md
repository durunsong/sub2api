# XorPay 微信扫码配置

适用于本 Fork 的网页充值和订阅购买。复用现有 XorPay 应用及支付宝配置；需要该应用已经开通微信支付。

## 后台启用

1. 更新前后端后，打开管理后台「设置 → 支付设置」。
2. 保持支付功能开启，在启用支付类型中保留「XorPay（支付宝）」，并启用「微信支付」，保存设置。XorPay 选项同时用于解锁该服务商卡片管理。
3. 编辑已有 XorPay 实例，保留 AID、App Secret 和回调域名，在支持的支付类型中保留「XorPay（支付宝）」并选中「微信支付」；启用实例并保存。密钥留空表示保持原值，不需要更换现有凭据。
4. 如果微信已由其他服务商提供，先在对应实例取消微信支付或停用该实例，再启用 XorPay 微信。界面沿用同一种可见支付方式的冲突提示。
5. 回调继续使用 `https://你的站点/api/v1/payment/webhook/xorpay`，需公网可达；不要改成官方微信的 `/webhook/wxpay`。
6. 用户购买页选择「微信支付」，应显示微信二维码与扫码提示；原支付宝入口仍可使用。

当前管理页通过服务商实例开关选择通道。若已有外部管理工具通过设置 API 管理多个微信 provider，可使用 `payment_visible_method_wxpay_source=xorpay_wxpay` 指定 XorPay；当前页面没有单独的来源下拉框。

## 协议与资金处理

- 同一个 XorPay provider：`xorpay` → `alipay`，`wxpay` → `native`；二维码取 `info.qr`，微信通常返回 `weixin://` 内容。
- 金额使用 CNY 两位小数字符串。签名仍为 `MD5(name + pay_type + price + order_id + notify_url + app_secret)`，UTF-8、小写十六进制，使用未 URL 编码的原值。
- App Secret 仅在后端签名/验签使用，不返回用户端；测试凭据全部虚构。
- 回调验签使用 `aoid + order_id + pay_price + pay_time + app_secret`。服务端按订单绑定实例处理，校验实付金额，复用状态更新和履约幂等，成功返回 HTTP 200 `success`。
- 查询接口不返回支付金额，因此成功状态本身不能替代已验签回调完成到账；回调必须正常送达。退款继续使用 aoid 与退款金额签名。
- 现有充值倍率、手续费、赠金、订阅购买/永久重置卡规则和历史订单不变。

## 验收与排查

部署后需人工用获准的小额订单做真实验收：生成二维码 → 微信付款 → 订单完成且余额/订阅到账一次 → 原支付宝仍正常。代码任务没有读取生产凭据、发起真实支付、执行退款或部署。

- `fee_error`：检查 XorPay 平台余额。
- `sign_error`：检查 AID 对应 App Secret、固定拼接顺序与两位小数金额。
- `pay_type_error`：确认当前应用支持微信 Native。
- `wechat_api_error`：记录 status 及渠道错误信息，核实商户微信开通状态与渠道限制。
- 已付款未到账：检查 XorPay 回调投递、公网域名/TLS/反向代理及服务端验签/金额错误日志；不要手动重复补款。

范围是 Native 扫码；微信公众号内一键 JSAPI、小程序及线下付款码不在此次实现内。同手机内支付需按扫码场景处理，不承诺浏览器直接唤起微信。

回退前先停止 XorPay 微信新下单，并处理完在途订单；没有数据库迁移。
