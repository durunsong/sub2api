# Sub2API v0.1.171 Fork 同步设计

日期：2026-08-05

## 目标

将官方 Wei-Shaw/sub2api `v0.1.170..v0.1.171` 的全部功能、修复、配置和测试同步到当前 Fork，并保持现有定制功能与业务口径不回退。升级后 `backend/cmd/server/VERSION` 明确设为 `0.1.171`；官方 tag 中仍为 `0.1.170` 视为上游发布遗漏。

## 同步策略

以官方 `v0.1.170` 为共同基线做三方增量整合：一侧为官方 `v0.1.170..v0.1.171`，另一侧为当前 Fork 相对 `v0.1.170` 的定制。官方新增文件直接引入；仅官方修改的文件应用官方增量；双方都修改的文件按语义人工合并，不使用官方整树覆盖 Fork，也不直接 merge 因历史压缩产生的大量伪冲突。

## 官方 v0.1.171 纳入范围

- 腾讯天御、阿里云验证码 2.0，以及 OAuth、Passkey、登录、注册、找回密码的人机验证门禁。
- Codex 出站身份统一、官方版本自动同步、降载与过载重试修复。
- composite 分组推理强度策略、OpenAI 重置额度缓存、模型广场计价修复。
- 订阅并发续期锁、退款余额不足强制确认、Stripe 退款幂等。
- 登录令牌并发刷新、计费失败用量留痕、Messages 临时错误切号、WS 终止事件和调度取消等修复。
- 官方对应配置、依赖、前后端 UI、国际化和测试。

## 必须保留的 Fork 能力

- Kiro：OAuth、调度、缓存模拟、粘性会话与 TTL、端点模式、Web Search、credits 计费、cache_read 口径、429 冷却。
- 用户侧 Kiro→Claude 品牌别名；管理端仍显示 Kiro。
- XorPay：创建、查询、回调、退款及前端支付宝支付体验。
- Access Ban：IP/CIDR、UA、IP+UA、邮箱后缀规则，认证与 Gateway 拦截，管理端 CRUD。
- Grok/Kiro 配额并存，迁移 157 CHECK 继续包含 `kiro` 与 `grok`；迁移 159/160 不回退。
- 提示词安全审计完整模块，并叠加官方 Responses `output_text` 解析修复。
- 套餐续期定制：活跃套餐叠加、过期套餐续期、日卡重置额度、备注追加；同时纳入官方并发锁。
- Ops 错误日志筛选删除、管理端批量删用户、Fork 首页/品牌/支付 UI、VersionBadge 禁用在线更新。
- Wire 注入保持 Kiro、Grok 及新增验证码等服务同时存在，Kiro 在 Grok 前。

## 冲突处理与数据流

每个双方修改文件对照基线、Fork 当前内容和官方 171 内容。先识别官方变更意图，再将其嵌入 Fork 当前结构。认证链路中新增验证码服务不得绕过 Access Ban；支付退款修复不得移除 XorPay；订阅锁必须包住 Fork 续期算法；Codex 和 OpenAI 改动不得影响 Kiro/Grok provider 注入；设置 DTO、公开设置与前端类型必须端到端一致。

无新增数据库迁移时不制造 Fork 私有迁移；若官方 171 无迁移，保持现有迁移序列。所有配置只同步示例和代码结构，不修改 `.env*` 或生产配置。

## 错误处理与兼容性

- 验证码按官方 fail-closed 规则处理，并保留原 Turnstile 配置兼容。
- 退款余额不足按官方 `require_force` 契约处理，前后端同步。
- 计费失败仍落用量记录且实收为 0，不改变 Kiro credits 独立口径。
- 新设置字段保持零值兼容，升级后原有 Turnstile 和 Codex UA 配置无需迁移。
