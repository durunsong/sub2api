# sub2api v0.1.172 同步计划与记录

## 目标

- 将官方 `v0.1.171..v0.1.172` 增量同步到当前 Fork。
- 以三方补丁方式合入 208 个文件的官方增量。
- 解决冲突时保留全部 Fork 定制，不以官方整树覆盖。
- 将 Fork 的 `backend/cmd/server/VERSION` 设为 `0.1.172`。

## 版本口径

- 上一次同步基线：官方 tag `v0.1.171`。
- 本次目标基线：官方 tag `v0.1.172`。
- 官方 `v0.1.172` tag 内的 VERSION 仍是 `0.1.171`。
- 本 Fork 按 release tag 明确使用 VERSION `0.1.172`。
- 版本差异属于上游 tag 内容遗漏，不回退 Fork VERSION。

## 三方补丁策略

1. 以上一次官方 tag `v0.1.171` 为共同基线。
2. 提取官方 `v0.1.171..v0.1.172` 的文件级增量。
3. 将增量应用到保留 Fork 定制的当前工作区。
4. 无冲突文件直接采用上游增量。
5. 冲突文件逐段合并官方修复与 Fork 行为。
6. 不使用官方版本整文件覆盖高冲突文件。
7. 对数据库、金额、订阅、权限和网关链路单独复核。
8. 最后按 release tag 修正 VERSION 并更新同步文档。

## 官方新增范围

- 安全头、客户端 IP、代理拨号超时等安全与网络加固。
- 上游响应模型采集、展示、筛选和错配审计。
- 新增迁移 `194_add_usage_log_upstream_response_model.sql`。
- 新增迁移 `195_add_usage_log_upstream_model_mismatch_index_notx.sql`。
- 订阅日额度按自然日午夜重置。
- 订阅分配、到期和月度窗口相关并发与边界修复。
- 金额写入前按数据库 `NUMERIC(20,8)` 精度量化。
- OpenAI Responses、Messages、WebSocket 和工具 schema 修复。
- Grok 兼容、缓存、405 处理及媒体链路修复。
- Antigravity Claude/Gemini 兼容与上游响应处理修复。
- 网关调度、计费、透传和上游错误处理修复。
- 腾讯验证码配置、校验和认证页面门禁修复。
- Ops 日志退避、筛选参数和错误详情修复。
- 模型广场价格、模型信息和前端展示修复。

## 必须保留的 Fork 能力

- Kiro OAuth、令牌刷新、调度、配额和模型映射。
- Kiro cache emulation、粘性会话、Credits 计费和独立 429 冷却。
- 用户端 Kiro→Claude 品牌别名，管理端继续显示 Kiro。
- XorPay 创建、查询、回调、退款和支付宝展示。
- Access Ban 的 IP、UA、IP+UA、邮箱后缀规则。
- Gateway 与认证路由中的 Access Ban 中间件。
- VersionBadge 隐藏“立即更新”，保留版本提示和 changelog。
- 支付金额与到账金额分离、用户端倍率隐藏等支付定制。
- 活跃套餐叠加、过期套餐续期、日卡和备注等订阅定制。
- Ops 条件筛选后批量删除错误日志。
- Fork 首页、品牌、组件和确认交互。

## 数据库迁移红线

- 迁移 `157` 的平台 CHECK 必须同时包含 `kiro` 与 `grok`。
- 不得采用仅加入 `grok` 的上游 `157` 原始约束。
- 迁移 `159` 创建 Access Ban 基础表，必须保留。
- 迁移 `160` 扩展 Access Ban 规则类型，必须保留。
- 新增官方迁移 `194`，记录上游响应模型。
- 新增官方迁移 `195`，建立模型错配查询索引。
- 迁移顺序和非事务迁移执行方式需保持有效。

## 冲突文件类别

- Wire 依赖注入与 provider 顺序。
- 账号测试、用量查询和模型列表服务。
- Gateway、OpenAI、Grok、Antigravity 转发链路。
- UsageLog schema、Ent 生成代码、查询与统计。
- 订阅分配、额度重置、到期与并发控制。
- 设置、验证码、认证和公开配置 DTO。
- Ops 日志持久化、筛选和前端详情参数。
- 前端平台类型、模型广场和用量列表。
- 支付服务、退款流程与 XorPay 接线。
- 高危迁移 `157`、`159`、`160` 及新增 `194`、`195`。

## 合并后关键复核

- `kiroTokenProvider` 保持在 `grokTokenProvider` 前。
- Kiro 与 Grok 均存在于平台常量、配额与账号链路。
- `IPBanService` 仍注入认证和 Gateway 路由。
- Kiro→Claude 仅改变用户端展示，不改变内部平台值。
- XorPay 类型、工厂、Webhook 和前端入口均存在。
- VersionBadge 未恢复在线更新按钮。
- 支付与订阅定制未被上游同名逻辑覆盖。
- 响应模型审计字段可写入、查询和筛选。
- 日额度重置使用午夜边界，不退回滚动 24 小时。
- 金额量化与 `NUMERIC(20,8)` 数据库精度一致。
