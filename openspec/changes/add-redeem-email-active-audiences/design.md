# 设计

- 采用现有分段多选协议；不另建邮件接口或引入新依赖。
- 活跃沿用 `MAX(usage_logs.created_at)`，以服务端 UTC 基准时刻向前减 7×24、30×24 小时，包含下界。30 天包含 7 天，不解释为 7–30 天。
- 所选范围取并集，每个用户返回一行；同时选中两种活跃范围时，近 7 天用户标记 `active_7d`。旧未活跃范围仍按自然月计算，月长造成的重叠也只返回一行。
- 搜索与事务内资格复核共享 SQL；用户状态、角色、邮箱、退订、单批 1000 人及独立余额码保持原约束。新增活跃范围默认不选，`zero_balance` 仍只能单独选择。
- 新增 `253_redeem_email_active_segments.sql` 放宽批次 CHECK，旧 SQL 不修改；旧批次仍合法。迁移只交付，在隔离测试库验证。回退应用可保留扩展约束，若已有活跃批次，不得直接收紧约束或删除记录。
- USD 面值、8 位精度、建批事务、幂等和失败重试完全复用现有实现。本次只改变收件人资格。
- 实现按一个纵向切片进行，先测试再实现，最后复核 diff 并按用户要求提交、push。
